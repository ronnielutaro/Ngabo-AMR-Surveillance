# ADR 0012 — v0.1 Investigation-Priority Signal Policy

**Status:** Accepted  
**Date:** 2026-08-28  
**Decision Owner:** Ngabo maintainer  
**Scope:** Hackathon v0.1.0 synthetic AMR surveillance demonstration  
**Policy Version:** `ngabo-signal-v1`  
**Config Version:** `signal-win7d-org-facility-ward-v1`  
**Algorithm Version:** `composite-priority-v1`  

---

## Context

Ngabo's deterministic surveillance pipeline (Milestone 2, Issue #47 / Epic #18) synthesizes downstream findings from resistance-profile similarity (Issue #45, ADR 0010) and temporal/location concentration (Issue #46, ADR 0011) into an actionable signal candidate.

Downstream Proof-Carrying Reasoning (ADR 0009) and autonomous A1 incident-brief assembly require machine-verifiable signal findings to establish that an unusual antimicrobial resistance pattern warrants investigation.

To preserve scientific safety, Clean Architecture (ADR 0003), and zero-human Taskmaster autonomy (ADR 0007 / ADR 0009), the Ngabo maintainer has established a closed, maintainer-approved policy governing composite signal scoring, baseline comparison, and trigger triage for the v0.1.0 demonstration.

---

## Primary Invariant

> **The output of this policy is an `INVESTIGATION_PRIORITY_SIGNAL` candidate.**  
> It is **NEVER**:
> - an outbreak declaration;
> - an outbreak probability;
> - a diagnosis;
> - a model-confidence score;
> - a clinical decision;
> - prescribing or treatment guidance.

Any documentation, naming, types, comments, tests, or UI representations introduced by this issue must preserve this distinction.

---

## Decision

Adopt the **Ngabo v0.1 Prototype Investigation-Priority Signal Policy** (`policy_version = "ngabo-signal-v1"`, `config_version = "signal-win7d-org-facility-ward-v1"`, `algorithm_version = "composite-priority-v1"`).

The policy enforces the following sixteen maintainer-approved rules:

1. **Candidate Cohort Scope**:
   - Evaluated across candidate cohorts defined by `(organism_code, facility_id, ward)` over the governed 7-day retrospective observation window `[window_start, window_end]`.
2. **Minimum Structural Gate**:
   - A candidate cohort may only trigger an investigation signal when:
     $$\text{ward\_organism\_count} \ge 3$$
   - Treat $3$ strictly as a **prototype investigation-candidate minimum** for the synthetic v0.1 demonstration. It is NOT a clinically validated outbreak threshold. Single-isolate ($k=1$) and two-isolate ($k=2$) cohorts do not trigger candidates.
3. **Phenotype Similarity Component ($c_{\text{phenotype}}$)**:
   - Defined as the mean of all valid unique pairwise `ProfileSimilarityFinding.similarity_score` values among isolates in the candidate cohort:
     $$c_{\text{phenotype}} = \text{round}\left(\frac{1}{\binom{N}{2}} \sum_{i < j} \text{score}_{i,j}, 4\right)$$
   - Uses the deterministic pairwise semantics governed by Issue #45 / ADR 0010.
   - A single isolate provides no similarity evidence; do NOT assign $1.0000$ to a single isolate.
   - If there is insufficient material pairwise phenotype evidence (e.g. non-comparable profiles), the evaluation fails closed as `INSUFFICIENT_DATA` and no signal candidate is emitted.
   - Do NOT renormalize weights around missing phenotype evidence.
4. **Location Component ($c_{\text{location}}$)**:
   - Uses the existing Issue #46 / ADR 0011 `LocationConcentrationFinding.location_concentration_ratio` ($=\text{ward\_organism\_count} / \text{facility\_organism\_count}$).
   - This ratio is already normalized into $[0.0000, 1.0000]$.
5. **Temporal Component ($c_{\text{temporal}}$)**:
   - Defined as:
     $$c_{\text{temporal}} = \min\left(1.0, \frac{\text{ward\_organism\_count}}{3.0}\right)$$
   - The denominator $3.0$ corresponds to the prototype minimum candidate size. Bounded within $[0.0000, 1.0000]$.
   - This is a deterministic prototype prioritization transformation, not an epidemiological probability.
6. **Synthetic Reference Baseline Component ($c_{\text{baseline}}$)**:
   - For v0.1, a deterministic synthetic/configured baseline count is approved because no governed historical facility baseline dataset currently exists:
     $$\text{configured\_synthetic\_baseline\_count} = 1.0$$
   - **Explicit Disclaimer**:
     > *A deterministic synthetic reference count used solely to exercise baseline-comparison behavior in the v0.1 hackathon hero. It is not learned, hospital-derived, epidemiologically validated, or clinically validated.*
   - Multiplier calculation:
     $$\text{baseline\_multiplier} = \frac{\text{facility\_organism\_count}}{\text{configured\_synthetic\_baseline\_count}}$$
   - Normalization:
     $$c_{\text{baseline}} = \text{clamp}\left(\frac{\text{baseline\_multiplier} - 1.0}{3.0 - 1.0}, 0.0, 1.0\right)$$
     where a $3\times$ or greater synthetic reference excess saturates the component at $1.0$.
   - The configuration must reject non-positive or zero baseline counts with `ValueError`.
7. **Approved Prototype Weights**:
   - $w_{\text{phenotype}} = 0.35$
   - $w_{\text{location}} = 0.25$
   - $w_{\text{temporal}} = 0.20$
   - $w_{\text{baseline}} = 0.20$
   - Weights sum exactly to $1.00$.
   - **Explicit Disclaimer**:
     > *Deterministic prototype prioritization weights selected for the synthetic v0.1 workflow so that all four governed surveillance components contribute to an interpretable investigation-priority score. They are not clinically validated, epidemiologically calibrated, or probabilities.*
   - Weights are fixed and must not be tuned ad hoc.
8. **Composite Score Formula**:
   $$\text{signal\_score} = \text{round}(0.35 c_{\text{phenotype}} + 0.25 c_{\text{location}} + 0.20 c_{\text{temporal}} + 0.20 c_{\text{baseline}}, 4)$$
   - Since each component $c_i \in [0.0000, 1.0000]$ and $\sum w_i = 1.00$, $\text{signal\_score} \in [0.0000, 1.0000]$.
9. **Trigger Rule**:
   - $\text{trigger\_threshold} = 0.7500$.
   - An `INVESTIGATION_PRIORITY_SIGNAL` candidate is emitted **if and only if**:
     $$\text{signal\_score} \ge 0.7500 \quad \text{AND} \quad \text{ward\_organism\_count} \ge 3$$
   - The threshold boundary is inclusive ($\ge$).
10. **Fail-Closed Missing Data Semantics**:
    - If any material component required to produce a valid score is unavailable or invalid, evaluation yields `INSUFFICIENT_DATA`.
    - Partial-weight renormalization is strictly prohibited.
    - No values may be imputed, and no human prompt is permitted.
11. **No-Signal Semantics**:
    - Materially valid cohorts that do not satisfy the structural gate ($k < 3$) or trigger threshold ($\text{score} < 0.7500$) yield `NO_SIGNAL` at cohort evaluation level, and no candidate is appended to the emitted signal tuple.
12. **Deterministic Cryptographic Signal Identity & Independent Recomputability**:
    - Derived as `sig-<sha256(canonical_payload)[:16]>`.
    - Canonical payload binds all material data and calculation parameters:
      - `algorithm_version`, `config_version`, `policy_version`
      - `baseline_saturation_multiplier`, `configured_synthetic_baseline_count`
      - `c_baseline`, `c_location`, `c_phenotype`, `c_temporal`
      - `facility_id`, `facility_organism_count`
      - `min_candidate_count`, `precision`
      - `organism_code`
      - `output_value`
      - `signal_score`, `status`
      - `supporting_finding_refs` (sorted list of strings)
      - `supporting_isolate_refs` (sorted list of strings)
      - `trigger_threshold`
      - `w_baseline`, `w_location`, `w_phenotype`, `w_temporal`
      - `ward`, `ward_organism_count`
      - `window_start`, `window_end`
    - Every emitted `InvestigationPrioritySignal` carries an immutable `policy_config: SignalConfig` snapshot containing all material calculation weights, thresholds, reference counts, and precision, allowing downstream deterministic verifiers to independently recompute the score and trigger decision without consulting hidden runtime configuration.
13. **Proof-Carrying References**:
    - Every emitted signal candidate carries exact deterministic finding references to all underlying #45 (`psim-...`) and #46 (`tconc-...`, `lconc-...`) findings that materially support it.
    - No model-generated prose or private reasoning can serve as proof authority.
14. **Closed Policy Enforcement & Runtime Boundary**:
    - `_resolve_governed_config` requires exact `type(config) is SignalConfig` across all public entry points. Subclasses, duck objects, mappings, and arbitrary objects fail closed (`TypeError`).
15. **Expected Hero Cluster Value**:
    - For the canonical hero Ward A *K. pneumoniae* cohort (`ISO-031`, `ISO-034`, `ISO-039`):
      - $c_{\text{phenotype}} = 1.0000$
      - $c_{\text{location}} = 0.7500$
      - $c_{\text{temporal}} = 1.0000$
      - $c_{\text{baseline}} = 1.0000$
      - $\text{signal\_score} = 0.35(1.0000) + 0.25(0.7500) + 0.20(1.0000) + 0.20(1.0000) = 0.9375$
      - Satisfies $0.9375 \ge 0.7500$ and $3 \ge 3 \implies$ **EXACTLY ONE** `INVESTIGATION_PRIORITY_SIGNAL` candidate emitted.
16. **Expected Contrast Behavior**:
    - Single-observation contrast records (Ward B *K. pneumoniae*, Ward A *P. aeruginosa*, Ward A *E. coli*, Ward B *E. coli*, Ward C *E. cloacae*) do not satisfy $k \ge 3$ and emit zero signal candidates.
